# Grok Imagine 第七組 Prompt 輸出規則 v1

Last updated: 2026-11-04

Status: 輸出原則與介面配置已由使用者確認；已實作並進行本機回歸。尚未進行 Grok 外部生圖驗收。

## 目的與範圍

PAGE1 新增一組供 Grok Imagine 測試的第七組 Prompt。它使用目前資料庫和本次生成的選值，以使用者提供的舊版 Prompt 為文字結構參考；舊版的兩組特定人物、服裝和場景不是固定內容，也不是要回復舊資料庫。

第七組接入既有輸出卡、收藏與 DLL 來源；既有自動裁切問題由另一個 Session 獨立處理。

## 已確認的輸出規則

1. **同一次生成**：使用與既有輸出相同的已解析人物、服裝、動作、場景、光線、相機與其他有效來源；不得重新抽選、額外消耗隨機數、改變選值或替使用者選擇新內容。
2. **不按景別裁切**：無論特寫、胸上、中景、牛仔或全身，均不因畫面可能不可見而省略有效的身形、衣物、配件、鞋襪、完整姿勢、支撐物、場景線索或攝影來源。已選景別、比例及攝影條件本身仍要保留。
3. **忠實於來源**：保留已生效來源的視覺語意與具體細節，包括材質、配色、版型、穿法、人物辨識、姿勢關係、場景、光線與成像。允許調整句序、補充最少必要文法、整理標點和空白，以及移除完全相同的重複內容；不以字數目標、模型推測或通用摘要刪除選定細節，不新增未選的視覺事實。
4. **自然串接**：以人物及外觀開頭，再視當次有效內容串接姿勢、穿搭、場景、光線與攝影／成像。使用自然句子、逗號與必要的句號；不強制 GPT 式分區標題，不添加 MJ 參數或內部控制、保護與 fallback 文字。順序應服務可讀性，不能改變來源含義。
5. **空值不補寫**：全無或沒有生效的項目不輸出占位內容；不得推測額外衣物、姿勢、光源、場景物件、視角或身分。必要的成年身分與現有主體身份解析沿用本次有效來源，不把舊例子的形容詞硬寫成每次的固定開頭。
6. **遵守已生效關係**：景別裁切以外的模式接管、服裝優先權、角色卡身份、角色歸屬、指定動作、固定構圖、仰躺表面及觀察式抓拍等，依本次有效解析結果處理。被其他來源接管而未生效的潛在選值，不因不裁切而重新啟用；不可將 A／B 角色來源混在一起。
7. **允許同時描述景別與畫外來源**：例如 `medium shot` 與已選絲襪、鞋子可以同時出現。此規則保證文字來源保留，不保證圖像模型會把所有項目放進畫面。

第七組是獨立輸出，不使用 `grokPrompt`、`zImagePrompt` 或 `midjourneyPrompt` 這些既有欄位的名稱來取代其歷史映射。畫面標籤為 `Grok Imagine`，收藏識別碼為 `grok-imagine`；既有六組契約不變。

## 資料流約束

現行 `generateSinglePrompt()` 在 `buildPrompts()` 之前呼叫 `sanitizeLocksForCloseupMode()`；`buildPrompts()` 也會先產生身形、姿勢、服裝和場景的景別投影。因此，單純重排現有 GPT／Z／MJ 完成文字，或只讀取已投影的模型，無法滿足第七組不裁切規則。

後續原型必須先釐清並取得 **景別裁切前、已完成非景別接管與相容解析的同次有效來源**，包括明確選定但僅因景別隱藏的內容。不得為取得缺失來源重新生成或額外抽樣，也不得把因其他接管而未生效的設定誤當有效選擇。對於目前因上游裁切而從未解析的隨機欄位，必須先查明是否有同次有效結果；沒有結果時不虛構或另行抽選，應記錄資料流缺口再確認處理方式。

完整 Pose Composer 來源及明確支撐關係需從同一次狀態取得；不修改共用 canonical 來源或既有輸出對投影姿勢的契約。角色卡的永久身份錨點及相容欄位、雙人 A／B、固定場景與仰躺表面，需依實際模式建立代表案例，不能套用一般單人假設。

## 規則驗收案例

固定 seed，紀錄選值及選項來源；排除執行時 ID／時間，使用相同 seed、案例與數量比較。以下為驗收目標：

| 案例 | 第七組預期 |
| --- | --- |
| 腰上中景＋已選褲／裙、襪與鞋 | 保留中景與全部有效下身、襪鞋來源及配色，不強制改成全身。 |
| 臉部／胸上景別＋已明確選定的服裝和動作 | 保留本次有效且僅因景別受限的選定來源；完整姿勢、手部、道具和支撐不依景別刪除。 |
| 同一套選值切換景別 | 景別相關文字可改變；除景別本身外，不因景別轉換遺失已生效的身形、服裝、姿勢和場景來源。 |
| 完整造型／外套接管 | 保留有效完整造型、顏色與外套；不復活被接管的一般衣物。 |
| 雙人／角色卡／固定構圖／仰躺／抓拍 | 保留模式的身份、角色歸屬、接管與必要場景／支撐來源；不額外生成新選值。 |
| 全無與未知來源 | 全無不輸出佔位；未知但已生效的來源保留原有效內容，不用泛化替代或猜測。 |
| 保護既有輸出 | 六組原有文字、selection、summary、structured 與隨機結果在相同條件下不變；舊收藏不批次改寫。 |

後續程式變更須先新增 focused fixtures，再執行 [AGENTS.md](../../AGENTS.md) 的 Prompt 與相容性驗證矩陣，包含修改前後同 count／seed 的 `scripts/validate_prompt_logic.mjs`、`npm run test:prompt-quality`、前端完整 gates、strict audit 及五個現行工作區的瀏覽器 smoke。輸出卡、複製、DLL 來源、Saved Cards 與匯入／匯出的範圍和相容性在接入階段另行驗證。

## 外部測試

先用相同現行選值建立自然串接與分段兩個候選版本，保留相同視覺資訊，只改排列／格式；現有輸出作參考組。Grok Imagine Speed、Quality 分開比較並記錄使用日期、模式、比例、參考圖和每次 Prompt，以人物、服裝、動作、場景和構圖的呈現情況評估。若服務支援固定 seed 則記錄並固定；否則重複多張，不能假稱同 seed。

本機文字回歸只能驗證來源和組裝契約；不證明 Grok 會忠實呈現全部要求，也不宣稱新版本的圖像效果已優於既有版本。

## 實作與相容性

在同次解析中，於景別裁切前保留當次已生效的服裝來源，再與人物、姿勢、場景及攝影等解析來源組裝第七組；不額外抽樣。執行時結果使用獨立的關聯，不更改既有六組輸出欄位及生成物件結構；使用者新收藏時，沿用既有 `extraPrompts` 格式保存。舊收藏維持原內容，不追補第七組。參考人物模式以參考圖為人物和穿搭來源，沿用既有模式限制。

歷史驗證工具只對經雜湊核對的本次引擎版本重建原始引擎，以執行未改寫的歷史比較；未知或經修改版本仍拒絕使用該還原路徑。

新收藏會保留第七組當次文字。收藏的「套用目前預覽」沿用既有選項還原與重新生成流程，並非載入當次全部解析快照：若極近景時的隨機解析結果沒有保存在既有選項中，重新生成可能無法重現該衣物，應以收藏中的原始文字為準。此限制不改寫既有六組的選項與還原契約。
