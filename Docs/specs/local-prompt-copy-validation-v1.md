# 局部 Prompt 文案調整：本機驗證 v1

日期：2026-11-23。文件編寫基準：`14912114afcf6d459fc8bfc0b5d36361bbd521de`。

使用者核准先調整 AGENTS.md 與獨立規格，完成後確認；本批只修改文件，不修改程式、測試案例、package scripts 或 CI，不 commit／push。本文定義後續局部文案任務的本機驗證方式；沒有新增自動分類器或快速測試命令。

## 1. 目的與效力

把既有單品的有限文案修改，與 renderer／相容性規則修改分開驗證。分類依實際差異及消費端證據，不依檔案副檔名、行數或主觀認定「只是改字」。

本規格由 [根 AGENTS](../../AGENTS.md) 引用，符合條件時優先於一般 Prompt 資料列及舊 authoring／feature 文件中一律執行完整前端門檻的要求。既有產品輸出契約、專項相容斷言、catalog 規則及使用者明確要求的完整驗證仍有效。舊報告的已執行案例、數量與歷史證據不改寫。

這是本機驗證範圍調整：保留所有原測試，減少每次局部任務主動重跑的廣泛套件；不宣稱每次本機驗證與完整歷史矩陣具備完全相同覆蓋。不能以本機局部通過宣稱 CI／部署成功。後續[純文件 CI 分流](ci-docs-only-v1.md)與[局部文案 CI 試點](ci-prompt-copy-v1.md)各自規範自動選測；未登記的局部單品仍走完整 CI。定期稽核與案例退休未啟用。

## 2. 適用條件：全部成立才使用

| 條件 | 必須具備的證據 |
| --- | --- |
| 既有且可列舉的項目 | 記錄每個既有 ID、所屬來源及實際消費端；不是新增／刪除／改名／合併選項。沒有 ID 的文案常數需列出名稱、所有引用及固定適用範圍。 |
| 差異限於描述文字 | 可調整既有描述欄位、對應中文說明或單品專屬字面常數；預期文字變化逐項列明。不修改程式條件、正則、函式、字串組裝演算法或資料結構。必要的專項測試與文件可隨文案更新。 |
| 選值與語意契約不變 | ID、顯示名稱、既有別名內容與順序（只允許下述舊英文尾端追加）、分類、meta.semantic、專用語意欄位、可見性／配色責任、選單排序與隨機池不變。記錄描述的視覺細節變化及「為何不需修改分類／有效語意」，不能只因 metadata 沒改就視為成立。 |
| 文字不改變控制行為 | 搜尋舊全文、關鍵片語、ID、常數引用及相關 consumer，核對名稱擷取、關鍵字推論、正則判斷、裁切、配色、互斥與 restore。歷史／自訂 library 的推論退路若會消費這段文字，也要列入評估。 |
| 儲存與舊資料仍相容 | 不改 codec、storage key、版本、legacy mapping 或 matching 順序；既有舊英文／ID 還原仍有效，舊卡保存的文字不被改寫。 |
| 本次差異可安全分離 | 先確認 branch、HEAD、工作目錄及相關 diff；其他未提交內容不納入本次驗證宣稱，也不 reset、暫存或覆寫。重疊而無法安全分離時先回報。 |

可調整視覺描述的用詞或補充已存在設定的細節；是否符合這條路徑仍由上述完整證據決定。例如補述肩帶去向，只有在既有辨識、aliases、配色與腰線規則不需改動時才符合。

**相容性不能為了快速驗證而省略。** 2026-11-24 核准窄例外：英文修改時，可在 `legacyPromptAliases` 尾端追加修改前完整英文一次，保留所有既有內容與順序，並驗證無碰撞、舊／新英文與舊 ID 還原相同項目；原已存在則不重複追加。除此以外的 alias 修改，或修改 MJ 完整片語辨識，仍升級完整門檻。既有 aliases 及 frozen seals 不得刪改。

歷史例子：[丹寧吊帶褲 v1](denim-overalls-low-hips-v1.md) 首次修改包含主 MJ 例外及腰線相容，屬完整門檻；2026-11-17 肩帶補充的紀錄也包含 alias 追加與 MJ 片語辨識更新，因此不能把該批全部差異直接歸類為本規格的純文案。未來修改要重新看當次 diff。

## 3. 開工前的最小驗證計畫

在修改前記錄：

1. 實際 baseline commit、Node 版本、來源檔案、既有 ID／常數及目前未提交內容；catalog 另記受信任的完整 `REGISTRY_BASE_COMMIT`，不沿用文件中的過期 SHA。
2. 每筆舊／新文案、允許出現差異的輸出及欄位；有效語意、選值、aliases 和控制行為應保持哪些值。
3. source → 正規化／解析 → 各 renderer → 預覽／複製／下游的影響範圍，及判定為局部文案的理由。
4. 專項測試檔、固定輸入／seed、景別與模式、配色／相容／還原案例、未修改代表案例，以及受影響的桌手機流程。列出不適用的情境與原因，不能默默省略。

用相同輸入、seed 與執行設定比較修改前後，除核准文案及其生成物外，其他來源版本保持一致；只排除既有動態 ID／時間戳。預期差異必須先寫清楚，不以修改後的輸出反推所有差異都合理。已有案例不足時補有意義的專項驗證；不能只截圖一段 Prompt 就判定通過。

## 4. 必要驗證對照

| 驗證面 | 必做／適用條件 | 通過標準與範圍 |
| --- | --- | --- |
| 來源差異與生成物 | 每次必做；catalog 只改 index 列管來源，再同步 | 只有核准文案及可追溯生成物改變；無順序、ID、語意旁改；alias 只允許核准的舊全文尾端追加。不可手改 database／生成 Markdown。 |
| Catalog 完整性 | 修改 catalog 時，保留 [catalog README](../../knowledge_base/catalog/README.md) 與 AGENTS 的來源流程 | sync、唯讀 check、schema／history、受信任 registry、strict integrity、相關 E 工具檢查照常；本例外不豁免這些資料檢查。只有 deployable assets 受影響時才增加相應資產檢查。 |
| 單品的公開輸出 | 每個受影響 ID 必做 | 依 [page1PromptOutputs](../../webapp/src/lib/page1PromptOutputs.js) 與各輸出契約列出當前所有適用公開輸出，包括 Nano／Grok Imagine 等，不只查舊四輸出。保留規定的名稱、全文或壓縮內容，沒有漏字、重複、語法錯誤或控制語言外洩。 |
| 景別與可見性 | 項目經過裁切／投影時必做 | 覆蓋該項目的可見、隱藏及投影邊界，包括適用衍生輸出與仍支援的 legacy 景別；不以全身一例替代裁切檢查。逐筆記錄測哪些景別及為何足夠，不擴成所有無關場景的交叉矩陣。 |
| 模式與人物責任 | 該項目可在單人、雙人、角色／固定／參考圖等路徑使用時 | 驗證實際受影響的分支；雙人檢查 A／B 不串接，獨立擁有來源的模式不被誤改。不能假設單人通過即代表所有模式通過。 |
| 配色與既有相容 | 項目有配色或穿法／互斥／腰線設定時 | 至少包含無配色、一般單色、不同語法的適用色彩，以及現存相容／不相容邊界；顏色作用對象、有效選值與停用／恢復保持。無配色能力等不適用理由須記錄。 |
| 穩定資料與 RNG | 每個受影響固定案例必做 | selection、有效 locks、ID、順序、語意 metadata 及 RNG 次數不變。structured 中的來源文字、summary／summaryFields 若依契約必然攜帶新文案，只允許事先逐欄列明的文字差異；不能略過整個資料欄位。 |
| 舊資料與還原 | 項目可保存、匯入或由舊文字辨識時必做 | 舊 ID／舊英文仍解析至同一項目，舊收藏原文不變；新選值保存後實際重新生成正確。依該項目真正使用的收藏／Markdown／ZIP／套用路徑選既有專項。 |
| 輸出契約與未修改代表 | 每次必做 | 執行相關契約／代表案例測試；另以固定 seed 比較未選到修改項目的同類單品及不同相關模式，核對文字、穩定資料與 RNG 不變。若隨機案例抽到目標，歸入目標案例，不能算作未修改對照。 |
| 靜態與建置 | 實際 Prompt 文案變更必做 | `webapp` 的 lint、build 通過；沒有因測試時間預算而略過。純規範文件修訂另依 AGENTS 的 documentation-only 列處理。 |
| 實際產品流程 | 公開 Prompt 文字受影響時必做 | 桌面／手機選取項目、預覽及複製的內容一致；適用時確認帶入 DLL 完整版或收藏套用。僅檢查實際受影響工作區及下游，不操作既有真實收藏、不發送付費生成。記錄 viewport、狀態、console／page error 與結果。 |
| 最終範圍 | 每次必做 | `git diff --check`、檔案／差異審閱，確認沒有改動其他未提交內容。 |

預覽與複製／DLL 來源會共用文字，不代表只看 renderer 單元測試就已完成下游驗證。局部路徑仍需受影響流程的桌手機檢查；不因文字顯示改變就自動擴成六工作區 smoke。若改了共用殼層、排版、生成行為或輸出消費邏輯，適用完整矩陣與 [視覺驗證規格](frontend-visual-validation.md)。

## 5. 現有執行入口與免跑範圍

本規格最初沒有快速入口；2026-11-24 的 CI 試點新增 `scripts/validate_prompt_copy.py`，只支援獨立規格登記的 profile，不能用來取代所有單品的本機驗證。執行前須依第 3／4 節選取實際現有測試，不得把以下例子當成適用所有單品的固定清單：

```sh
# 在 webapp/ 執行：輸出契約與其現有代表案例
node --test src/lib/engine/promptOutputContracts.test.js

# 丹寧吊帶褲的既有專項入口；其他單品要換成自己的適用測試
node --test src/lib/engine/denimOveralls.test.js

npm run lint
npm run build
```

這些檔案確實存在，但上述命令本身不保證涵蓋所有公開輸出、同 seed 前後比較或下游。必須補齊第 4 節的實際案例／證據；必要時新增專項。若既有 feature 測試含耗時歷史檢查，不能直接刪掉斷言或用名稱篩選略過失敗；仍執行它，或另案審核如何拆分。

Catalog 檢查的命令、環境與基準依現行 README 執行；本文不提供可被誤用的固定歷史 SHA，也不修改其工具或檢查範圍。

條件成立且必要驗證齊全時，本機不因這次文案變更而自動執行完整 `npm test`、整份 `test:prompt-quality`、全域 `audit:prompts:strict`、無關大型歷史矩陣或六工作區 smoke。以核准的逐項／代表案例及相同 seed 比較承接本批本機檢查；全域 audit 的案例數／seed 不得在報告中偽稱已執行。

必要項目是否通過是完成標準；本文件尚未量測採用新規則後的實際耗時，不承諾固定完成時間，也不設定超時即可停止驗證的門檻。

## 6. 升級完整測試的規則

下列任一情況，改依 AGENTS 的完整 Prompt-data／renderer／compatibility 列：

- 新增／移除項目，改 ID、名稱、超出舊全文尾端追加例外的 alias、分類、語意、排序、隨機資格／權重、schema 或對外欄位。
- 修改 parser、關鍵字辨識、正則、分支、共享字串組裝、配色、裁切、衝突、角色接管、codec、legacy mapping 或儲存遷移。
- 文案被多處／不同 owner 消費，無法完整列出影響；或需修改識別／還原邏輯才能支援新文字。
- 未選到目標的輸出也改變，或 selection／語意 metadata／RNG 有未核准差異；無法以局部證據解釋的失敗。
- 原測試／基準不足，無法建立可靠的修改前後對照或覆蓋必要分支；或本次任務明確要求完整驗證。
- 本批混入任何不符合局部條件的修改。若是同工作區其他人的獨立未提交內容，先保持其原樣並界定驗證來源，不把它們自行納入或還原。

已知且符合核准文案的專項斷言，可連同測試理由作窄幅更新；這不等於可重錄不可變歷史 seal。精確歷史修訂仍依原機制保留 before／after 與來源證據、執行其相關驗證；若需要改 replay 邏輯或改變歷史比較契約，就升級完整門檻。既有不相關失敗要證明並報告，不擴張修改範圍來消除它。

升級後的本機範圍是：相關專項、完整前端 `npm test`／`test:prompt-quality`／lint／build、相同 count／seed 的 strict Prompt audit 與六工作區 smoke，加上實際來源所需 catalog 等檢查。缺依賴、歷史或環境時記錄未完成項，不宣稱完成。

## 7. 分類示例

| 當次實際差異 | 分類與原因 |
| --- | --- |
| 既有衣物描述補細節，全部消費端仍使用相同 ID／規則，無需改 alias | 可評估局部路徑，完成全部適用專項後才成立。 |
| 只改 JS 中單品專屬文字常數，引用與控制行為不變 | 可評估局部路徑；不能只因改到 `.js` 就排除，也不能只因是字串就放行。 |
| 換了英文，只在 alias 尾端追加完整舊英文 | 可評估局部路徑；需完整保留既有陣列，驗證碰撞與新舊還原。 |
| 調整其他 alias 或 MJ 片語辨識 | 完整路徑；不能漏做相容性保護。 |
| 新增一件衣服或一個場景，其他程式不改 | 完整路徑；選單／來源集合或隨機池可能受影響。 |
| 描述維持，但改 meta.semantic、支撐、配色責任或裁切欄位 | 完整路徑；是有效行為調整。 |
| 文案改動後其他單品輸出或 RNG 也不同 | 升級完整路徑並調查，不更新預期掩蓋差異。 |
| 只修改本規格及 AGENTS | 文件審閱、連結／路徑、規則一致性與 diff 檢查；不因此啟動產品或 CI。 |

## 8. 任務回報與後續授權

回報須包含 baseline、ID／來源清單、分類理由與消費端檢查、實際案例及 seed、執行命令／結果／耗時、合理不適用項、桌手機證據，以及未在本機執行的廣泛套件。若升級，說明觸發原因。把本機驗證、CI、部署及外部模型效果分開記錄。

本文原始交付未變更 [.github/workflows/deploy.yml](../../.github/workflows/deploy.yml)、`webapp/package.json`、測試 runner 或歷史案例。後續純文件分流與局部文案 CI 試點由各自獨立規格承接；不符合登記試點的 Prompt 資料及程式 main push 仍執行完整測試。進一步擴增 profile 或定期稽核仍需另案實作與驗收。提交、推送、部署須依任務授權。
