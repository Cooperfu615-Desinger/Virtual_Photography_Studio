## 1. 目的與範圍

在 PAGE1 既有六份輸出之後新增第七份「局部超特寫」，內含眼部、鎖骨／胸口、腰腹／肚臍三種拍攝目標，每次顯示一份自然英文 Prompt。第一版僅支援單人。

本方案取代先前討論的「局部拍攝模式」：不接管 Gpt、Z-Image、AI，不新增全局模式開關，不鎖定或清除主要工作台的場景、景別、角度與焦段。一般攝影設定仍服務原有輸出。

不在本次處理：雙人目標人物選擇、左右眼控制、局部角度／強度控制、三套模型專用局部文案、其他外套版型或開合衝突、原有六份輸出的優化。

## 2. UI 與操作

- 卡片名稱「局部超特寫」，置於全身角色照之後，沿用既有輸出卡片視覺，不重排前六張卡片。
- 卡片內提供「拍攝部位」：眼部、鎖骨／胸口、腰腹／肚臍。新生成結果首次使用預設眼部；使用者已選的部位可作為後續生成偏好，但不得納入人物／穿搭隨機池。
- 提供英文文字預覽及複製。圖像生成來源清單新增對應選項，來源文字必須等於當前局部卡片文字，不呼叫外部生成服務來切換部位。
- 提示：「使用目前人物與穿搭的局部細節；不沿用一般景別、鏡頭角度與場景。衣物覆蓋的部位將呈現衣料細節。」
- 尚無結果時顯示等待生成狀態；雙人結果不建立局部輸出或圖像來源，不默默改拍其中一人。
- 切換部位只能改變局部輸出；不可重新抽取人物、服裝、配件、光線，不改動既有六份文字或 raw selection。
- 保存的是當下結果與部位，不隨日後工作台設定改變。舊卡沒有此輸出時不虛構第七份；需重新生成才建立。

## 3. 資料流與隔離

同一次解析結果應分為獨立消費路徑：

```text
原始設定 → 一次解析的人物／穿搭／姿勢／場景／成像資料
              ├─ 既有主輸出投影 → Gpt／Z-Image／AI（不變）
              ├─ 既有衍生投影 → 胸上照／MJ 胸上照／全身角色照（不變）
              └─ 局部部位投影 → 局部超特寫（新增）
```

局部投影從原始解析資料建立，不從主 Prompt 文字裁句，不從已被主景別刪減的 wardrobe 回推，不用同一 seed 重新生成冒充同一結果。

切換部位可使用預先計算的三份局部文字或同一份不可變解析快照；實作時擇一，但必須通過結果一致性測試。不得把完整共享模型刪成局部模型，否則會污染 MJ 胸上照目前借用主模型的路徑。

既有 `faceDetail`、`chestUp`、`mediumWaist` 不是本功能的替代品：它們保留的部位範圍較廣、場景仍有來源片語，仰躺亦有保留完整表面的例外。局部輸出使用自己的明確允許清單；場景為真正空值，不以未被程式支援的 mode 字串假裝已省略。

## 4. 三個部位的保留／省略矩陣

| 類別 | 眼部 | 鎖骨／胸口 | 腰腹／肚臍 |
| --- | --- | --- | --- |
| 中心與裁切 | 從眉線延伸至上眼頰，雙眼與眼瞼位於區域中心；嘴、下巴、頸部與完整臉孔留在畫面外 | 從頸根延伸至上胸，保留雙側鎖骨區與已選領口／肩帶；臉、手臂、腰部與下軀幹留在畫面外 | 從下肋骨延伸至上髖線，肚臍靠近中心並保留兩側自然腰線；頭部、手臂與雙腿留在畫面外 |
| 身份細節 | 來源中明確的眼型、眉型、眼周特徵 | 該區有來源的皮膚特徵 | 該區有來源的皮膚特徵 |
| 膚質 | 可見眼周適用部分 | 可見胸口適用部分 | 可見腹部適用部分 |
| 表情 | 僅眉眼相關部分 | 省略 | 省略 |
| 頭髮 | 明確可能遮住眼部的瀏海／髮絲 | 明確垂落至該區的局部髮絲 | 省略 |
| 服裝 | 省略一般服裝；保留確實遮住眼部的穿戴物 | 衣料、顏色、領口、肩帶及影響該區覆蓋的穿法／開合 | 衣料、顏色、腰線及影響該區覆蓋的衣襬／開合 |
| 配件 | 眼前鏡框／鏡片；戴在頭上的眼鏡不強制入鏡 | 位於該區的頸圈、項鍊、墜飾 | 位於該區的腰飾、肚臍飾品 |
| 局部身形錨點 | 省略 | 只保留來源中與上胸輪廓有關的片語，例如胸型／肋骨輪廓；不帶完整身高、三圍或腿身比例 | 只保留來源中與腰腹輪廓有關的片語，例如腰線／腹部長度；不帶完整身高、三圍或腿身比例 |
| 完整體態 | 省略身高、體重、三圍、全身比例 | 仍省略完整身高、體重、三圍、全身比例 | 仍省略完整身高、體重、三圍、全身比例 |
| 畫面外內容 | 省略嘴唇、完整臉型、整套髮型與穿搭 | 省略完整臉孔、髮型、上下身清單、鞋包 | 省略臉孔、髮型、胸口、鞋包 |

所有保留內容必須可追溯到當次已解析來源；無資料不補眼色、雀斑、毛孔、汗水、露膚、飾品或其他新視覺事實。局部身形錨點只在胸口／腰腹使用，且不使未知衣物變成 ready。配件只描述局部可見部分，不為完整展示長鏈條或墜飾而拉遠構圖。

### 4.1 範圍式構圖句

三個 target 使用同一套「區域範圍 → 中心焦點 → 可保留邊界 → 明確排除畫外部位」語法。正式英文句由 `localDetailProjection.js` 維護，target id 不變：

- `eyes`：從眉線到上眼頰，保留雙眼、眼瞼、近眼髮絲、眼鏡與局部皮膚；嘴、下巴、頸部與完整臉孔排除。
- `collarbone-chest`：從頸根到上胸，保留鎖骨區、領口／肩帶、局部髮絲、衣物邊界與頸部配件；臉、手臂、腰部與下軀幹排除。
- `abdomen-navel`：從下肋骨到上髖線，肚臍靠近中心並保留自然腰線、衣物邊界與已選腰部配件在裁切邊緣的局部；頭部、手臂與雙腿排除。

這些構圖句不會自行讓位置未知的配件入鏡。腰鍊、吊墜等仍依 B 批來源位置／層次證據處理；「selected ... remain visible where they enter the crop」是局部構圖邊界，不能取代配件的來源審核。

### 4.2 寫實局部輸出的身份開頭

當成品類型為「寫實攝影」時，眼部、鎖骨／胸口、腰腹／肚臍三個 target 共用下列第一句，先建立單一、年齡與國籍範圍明確的女性主體：

`Photorealistic editorial detail image, A 20s seductive stunning Japanese or Korean woman.`

這句由局部成品類型層輸出，不能在三個 target 的構圖句中重複。水彩、油畫、時裝插畫與粉彩插畫保留各自的成品身份開頭，不被強制改成 photorealistic。

## 5. 衣物覆蓋：優先於部位可見性

「拍攝部位」指定位置，不承諾該位置的皮膚一定露出。

| 狀態 | 局部輸出 |
| --- | --- |
| 明確露出 | 可見皮膚／部位與附近衣料邊緣 |
| 明確遮住 | 覆蓋該位置的衣料；不要求透視看見皮膚或肚臍 |
| 明確半透明 | 保留來源的透膚程度；不改成全裸或不透明 |
| 資料不足 | 不推定露膚；僅輸出已確認的覆蓋／材質。若連衣物局部身份也無法確認，回傳內部待補資料狀態並停用該部位複製／圖像來源，不輸出完整穿搭作 fallback，也不虛構衣料 |

覆蓋要合併外套、內搭、連身／套裝及有效開合；外套敞開不等於內搭也露腹。衣服遮住的肚臍飾品不寫成可見；不得為顯示它而開洞、拉低領口、改成短版、拆開連身服。

實作前應盤點來源能否支援區域判定，必要時建立可審查的部位描述／覆蓋 metadata。不能只用 `navel`、`chest`、`button` 等關鍵字猜所有複合穿搭；本文件不代表現有資料已具備完整覆蓋模型。待補資料提示是保護性降級，不是驗收完成：正式支援範圍及未支援選項需列明。

## 6. 共同輸出契約

- 結構：成品形式 → 局部取景成果 → 可見特徵 → 局部衣物／配件 → 適用光線與成像。
- 成品形式沿用當次選擇；攝影使用局部 detail image 取向，不套用完整人像開頭。插畫等不能被強制改成 photorealistic。
- 寫實攝影的局部成品形式固定包含 `A 20s seductive stunning Japanese or Korean woman` 身份錨點，三個 target 共用同一句；其他成品類型仍使用各自的 image-type opening。
- 明確指定目標區域主導畫面及允許邊界裁切；不要求完整人物、完整衣物或配件。不要只有「允許裁切」而沒有中心。
- 三個區域採範圍式構圖：眼部為眉線至上眼頰、胸口為頸根至上胸、腰腹為下肋骨至上髖線。身形只可透過目標相關輪廓錨點補充，不能重新帶入完整體態。
- 不沿用一般景別、俯仰／環繞角度、焦段與其幾何句。不新增數值焦段、強制正上方視角或固定左右側。
- 不輸出完整姿勢、手部動作、自拍／遮鏡構圖、道具、接觸支撐；仰躺床鋪／海面及其造景亦不保留。濕髮等獨立可追溯可見設定按局部規則處理，不因水中場景自動補濕潤。
- 固定構圖、場景基底、匯入場景、場景點綴全部省略；不補白底、黑底或散景背景。
- 光線保留有來源的局部亮度、色溫、柔硬度、方向；不帶入窗戶、房間、地面等物件。混合式描述需有可追溯局部版本，無法安全拆分的來源先省略並記錄內部診斷。
- 色調、表現形式與不要求拉遠構圖的成像效果可保留；不能機械搬入人物／場景型攝影師長描述。效果可追溯，互斥問題不得藉本功能擴大改寫一般輸出。
- 第一版一份英文，不添加 Midjourney 參數尾巴或 GPT `multi-cut sequence n=2`。不新增固定輸出比例；圖像生成比例仍是生成器設定，不改動既有比例控制。
- 不輸出 `全無`、`none`、fallback、projection、guard、停用原因等內部語言。內部診斷與 UI 提示不能串入公開 Prompt。
- 角色卡完整身份資料保持原樣；僅此新增局部輸出可省略畫面外永久身份錨點。既有六份輸出及四身份錨點契約不變，不能以舊的全身份檢查迫使局部輸出補回整張臉。

## 7. 儲存、複製與相容性

- 輸出 id 固定為 `local-detail`，部位值固定為 `eyes`、`collarbone-chest`、`abdomen-navel`；不變更既有 id 或 public field mappings。
- 每份可保存局部輸出需包含穩定 id、標籤、目標部位、實際英文文字及契約版本；確切 JSON 欄位位置由實作與 codec 測試共同固定。未知欄位不可只加在 UI 後假設匯出會保留。
- 保存／匯出當下選定部位及文字。還原後先顯示保存的文字，不以新版本引擎悄悄重寫；切換其他部位若缺少相同解析快照或預先計算結果，必須提示需重新生成，不以目前工作台資料混搭舊卡。
- 既有 JSON／壓縮記錄與支援的 Markdown 匯入匯出路徑需各自驗證。現行 Favorites codec 版本為 v4，保存 `localDetailPrompts` 的三部位安全欄位及 `localDetailTarget`；v2／v3 舊記錄仍可讀，沒有局部欄位時不合成第七輸出。Markdown 使用 `## Local Detail` 的 JSON fenced section 保存契約版本、選定部位及三份預先計算文字；沒有該 section 的舊 Markdown 仍按舊契約處理。ZIP 沿用同一 Markdown codec；ZIP 既有獨立 round-trip 問題不在本次修復範圍，不宣稱已解決。
- 來源、選項、全無／隨機語意與舊 `extraPrompts` 不改名、不重排既有輸出。舊卡不批次遷移，不刪除退役輸出的相容處理。
- 未支援／缺資料時不能將其他主 Prompt 偷換成「局部超特寫」來源；複製與生成按鈕依現有互動模式顯示不可用原因。

## 8. 驗收矩陣

1. 同一 seed、同一原始設定，新增功能前後既有六份文字逐字一致，排除 runtime IDs／timestamps；切換三個部位不增加隨機呼叫、不改 raw selection。
2. 三部位各覆蓋：一般上下身、連身、套裝、外套疊穿、角色卡、特殊穿搭；無可靠局部資料時檢查明確降級，不臆造覆蓋。
3. 覆蓋露出／不透明／半透明、內搭遮蔽、外套正常／單肩／雙肩及開合；被覆蓋的身體與飾品不得被強制顯示。
4. 眼部的鞋款／裙長／場景變更不得影響局部輸出；胸口的鞋包變更同理。應使用同一解析快照的單因素變更測試，避免隨機序列變動干擾。
5. 全身／臉部景別、魚眼、背面、固定構圖、仰躺表面、匯入場景、自拍及遮鏡手掌不滲入局部 Prompt；一般輸出仍照原設定生成。
6. 三主輸出與既有三衍生輸出維持自身契約；新增局部獨立契約，不套用要求完整身份或完整人像段落的舊檢查。
7. 第七張卡片、部位切換、複製、圖像來源、缺結果／雙人／缺資料狀態、保存／還原／匯入匯出皆有測試。舊六輸出卡與舊資料仍正常。
8. 按 AGENTS 驗證：focused tests、Prompt Quality、完整 test／lint／build、同 seed/count strict audit；若補來源 metadata，再跑相應 sync／資料測試。診斷數與阻擋分開報告。
9. Browser：指定本機 URL，1440×1000、390×900，局部卡片三部位切換及 downstream consumer，五工作區導覽；確認不重新隨機、無新錯誤／意外橫向溢出。不得為 QA 擅自付費生成外部圖片。
10. 程式與瀏覽器通過不等於跨模型生圖通過。提供固定來源的三部位測試 Prompt，讓使用者確認局部構圖與服裝覆蓋，再記錄實測限制。

## 9. 實作順序與現況

1. 建立局部輸出契約、三部位 fixtures、覆蓋資料盤點；先確認來源與支援缺口。
2. 實作獨立局部投影與 renderer，證明舊六輸出不變。
3. 接入輸出卡片、部位狀態、複製／生成來源。
4. 完成自動測試、Browser QA 與使用者生圖測試交付。

目前 consumer 與保存階段已完成：`page1PromptOutputs.js` 以顯式 consumer 選項提供第七張卡與 DLL 來源，`LocalDetailPromptCard` 只切換同一次解析的三個預先計算結果；雙人／缺少 bundle 不建立來源。`cardCodec.js` 與 `localRepository.js` 保存三部位的 stable id、label、target、英文文字、契約版本與目前選定部位；Markdown 匯出／匯入讀寫同一份局部 JSON section。套用 Saved Card 時先顯示保存文字，同一張卡的其他已保存部位可切換；使用者重新編輯或 reroll 後才解除保存快照並回到當前工作台結果。

第一階段交付：`webapp/src/lib/engine/localDetailPromptContract.js`、`localDetailPromptFixtures.js`、`localDetailPromptContract.test.js` 與[覆蓋盤點](local-detail-coverage-inventory.md)。十組來源案例是目標規格與來源可追溯性測試，不是已生成英文成品。契約加入內部 mixed 子區域狀態，以處理鎖骨露出但胸口覆蓋等情況；不增加 UI 選項。
