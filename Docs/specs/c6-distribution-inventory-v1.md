# C6 資料分布盤點與唯讀量測 v1

日期：2026-10-31。審閱基準 main：`bfa5311d13d738bfb42051f69dc656880d08b6e9`。
範圍：盤點文件、保留理由、唯讀量測工具與測試；不擴充內容、不改抽樣規則。
狀態：本批實作與本機驗收見[報告](../reports/c6-distribution-2026-10-31/README.md)，使用者已授權限定 commit／push；CI 與部署於交付時另行核對。

## 1. 目的與三種計數

將姿勢、地點、季節、穿搭、角色的「資料存在」「介面可選」「特定設定下實際抽到」分開，避免以歷史組合器、文字關鍵字或有限抽樣推論產品缺陷。

| 層級 | 來源／口徑 | 不代表 |
| --- | --- | --- |
| 正式目錄 | index.json 所列分類 JSON；rows 含全無，content 排除全無／隨機 | 不等於介面列數；不包含所有程式內嵌角色／動作 |
| 現行介面來源 | 實際 lock controls、PAGE1 selectors、已審閱 picker 篩選；指定動作與角色模組另計 | 不等於所有模式都啟用，也不是瀏覽器實際操作驗收 |
| 固定情境抽樣 | 指定 seed／locks，直接呼叫現行 generatePrompts；每情境保留命中次數、ID、RNG 次數、輸出雜湊 | 不是使用者操作遙測、平均使用率或生圖品質；未抽到不證明不可達 |

正式目錄共 1,050 列／1,008 非全無內容，但包含歷史資料，不能稱為 1,008 個現行 UI 選項。詞彙分類是可重疊診斷，不能加總成互斥人口、季節或風格比例。

## 2. 目前盤點

### 姿勢

- 現行指定動作 54：站 21、坐 14、跪 9、蹲 4、躺 5、上身互動 1。42 accepted、12 pending；pending 仍可手選並顯示狀態。
- 一般隨機池 38：站 10、坐 14、跪 9、蹲 4、上身互動 1。另 4 筆 accepted 躺姿，僅在鎖定相容場景時加入；不因隨機尚未選到場景便先開放躺姿。
- 三組各 1,000 次一般全身指定動作隨機，合計坐 1,087（36.23%）、站 791（26.37%）、跪 723（24.10%）、蹲 337（11.23%）、上身互動 62（2.07%）。未鎖場景故沒有躺姿。鎖白色床鋪另測 500 次，躺姿 40 次，四筆都可抽到。
- `selection.poseBaseId` 是保留的相容欄位，指定動作時可能仍為 none。分類必須以已解析的 `specifiedActionId` 對應現行動作 baseId；none 在該動作表代表上身互動，未選具體動作則另記 unset。
- 退役 Pose Composer 與舊姿勢資料不能混入現行分母。舊報告的坐姿占比不沿用，不重新公開舊姿勢，不啟動 P5b。

### 季節

### 角色

33 張角色卡均保留且可由角色選擇來源取得；32 張 identityAndBody 明文為成年東亞女性、1 張幻想角色；33 張均有 20 歲成年身份。33 張 facialGeometry 含 oval，但還有心形、圓潤、下顎、眼瞼等具體差別。skinSignature 中 fair／pale／porcelain 命中 30、light-olive 2、beige 2，分組重疊，不能相加成 34 張，也不作圖片族群推斷。

這八個情境均未要求隨機角色卡，characterProfileId 為 none 是預設契約；不能因此判定 33 卡不可達。C1 已補強 Natsuki／Miku 現有錨點；不為平衡統計改寫舊角色。新年齡／膚質／臉型角色需先有新內容需求與參考資料，另行決策。

## 3. 唯讀量測契約

- 入口：`scripts/c6_distribution.mjs`；實作與診斷政策：`scripts/lib/c6Distribution.mjs`、`c6DistributionPolicy.json`。
- Node 22＋既有依賴。只讀來源，在記憶體呼叫純引擎，JSON 寫 stdout；不呼叫供應商、瀏覽器、網路，不寫使用者收藏、不同步資料、不內建 report 寫入或重錄歷史模式。
- `--inventory-only` 不生成 Prompt；`--count N` 範圍 1..10000，預設 N=1000。全身 a/b/c、預設、特殊穿搭各 N；室內／戶外／鎖床各 floor(N/2)，最少 1。預設總計 6,500 次。完整 locks、種子及 count 隨結果輸出。
- 「full-random」是本工具命名，設定為一般單人、全身、指定動作隨機、套裝隨機；不是 UI「全部隨機」按鈕，更不涵蓋所有排除模式。預設情境使用 createEmptyLocks。其他情境單獨統計，不合併宣稱產品整體機率。
- `unique` 包括 none／unset 這類實際值；清單與 counts 可辨識其意義。outfit 合併已解析 outfitPresetId／dressId，兩個原欄位也保留；不含所有穿搭單品。unseen 是此情境未觀察到，不是不可達清單。
- 輸出雜湊只移除 runtime id／date，保留其餘完整 Prompt 物件；同 seed 重跑應完全相同。記錄 RNG 次數，不增加或替換產品抽籤。
- UI 中自行重現的已審閱篩選以四份來源檔 SHA 保護；檔案改變即拒絕沿用，先重審規則才更新政策。此診斷政策不被產品匯入，也不因本批加入部署 CI 門檻。
- 執行前後核對已追蹤 webapp/src 與 knowledge_base 的合成 SHA；驗收另對全部既有追蹤檔、歷史報告與其他工作目錄核對。測量數字是基準版本快照，未來內容變更需新批證據，不覆寫本批快照。

## 4. 保留與後續順序

決策與保留理由見[決策文件](../decisions/2026-10-31-c6-retention.md)及[逐項清單](../reports/c6-distribution-2026-10-31/retention-decisions.json)。現有數量不設平均配額，pending 與相容資料也不因統計較低直接刪除。

若之後需要擴充，建議依序：確定常用場景需求 → 小批自然／季節場景 → 有明確視覺差異的穿搭或獨立包包功能評估 → 新角色參考與身份設計。每批先審閱 ID、來源、可見性與相容規格，再做同 seed 比較與必要瀏覽器／模型驗收。這是候選順序，並未批准實作。

艾爾莎隨機選取維持現況，PAGE2 舊匯入、J12、P5b 繼續暫緩。C1 生圖辨識與原生下拉 popup 的既有驗收限制保留；本批不宣稱已解除。

## 5. 本批驗收

1. 純工具測試：sentinel／去重／文字選項／退役及分組篩選；UI 來源漂移拒絕；關鍵字不冒充語意分類；CLI 拒絕非法數字與寫檔旗標；同 seed、輸入不變與產品位元不變；指定動作及連身相容欄位量測。
2. 6,500 次完整量測重跑兩次，JSON 逐位元相同，核對八個情境及總數；不是只比較聚合百分比。
3. 唯讀 sync、目錄 strict 與現有目錄工具測試；文件路徑／數字核對及 diff-check。
4. 所有產品來源及歷史基準不變。因只有文件與離線工具，本批不重跑前端全套／build／瀏覽器／歷史 Prompt 回放，不將前批通過記作本批新驗收。無 UI 變更或付費生圖。
5. 保存首次失敗與修正原因。使用者已授權限定交付；CI／部署結果另行核對，不追寫原始驗收快照。
