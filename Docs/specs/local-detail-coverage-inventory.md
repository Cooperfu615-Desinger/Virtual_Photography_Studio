日期：2026-09-09。範圍：資料契約、來源證據測試、資料缺口；非生成或生圖驗收。

本文保留第一階段歷史盤點。後續已接入的來源與第一版有限範圍，請以[第一版覆蓋矩陣](local-detail-v1-coverage-matrix.md)為目前索引；以下「下一階段／尚未建立」是當時狀態，不代表現在所有 adapter 都尚未實作。

## 1. 結論

可在不改既有六輸出的前提下先建立獨立契約，但不能宣稱目前整個服裝目錄已支援局部輸出。現有來源提供衣料、衣型、部分露膚與開合的英文證據；大多沒有「目標部位 → 子區域覆蓋 → 可見片語」的明確資料。

本次不改任何服裝英文、目錄 metadata、生成流程、UI 或 codec。已有的其他外套問題仍暫緩。十組 fixture 的 `expected` 是下一階段的目標行為，不是目前 renderer 的結果。

## 3. 已核對的十組來源案例

完整可執行來源引用見 `webapp/src/lib/engine/localDetailPromptFixtures.js`。測試逐一檢查 category、中文名稱唯一存在及英文 excerpt；來源改動後會提示 fixture 過期。

| 案例 | 證據與預期邊界 |
| --- | --- |
| 甜美可愛臉 → 眼部 | `bright friendly eyes` 可作眼部來源；不搬入完整臉型或其他五官 |
| 眼鏡戴在頭頂 → 眼部 | `eyes unobstructed`；不強制鏡框入鏡 |
| 一字領上衣 → 胸口 | `open collarbone line` 只證明鎖骨開口，不證明整片胸口裸露 |
| 亮面乳膠束帶套裝＋肚臍環 | `continuous unbroken coverage` 明確連續包覆；肚臍飾品不能迫使開洞 |
| 高領挖腰連身泳裝 → 肚臍 | 原文明確露出腹部與肚臍；不能錯套「所有連身都遮腹」 |
| 亮面乳膠拉鏈洋裝 → 肚臍 | 開口延伸至肚臍以下；只是中央狹長開口，不能改成整片露腹或上下兩件 |
| 透膚刺繡襯衫 → 胸口 | 已知半透明材料，但內搭與子區域尚待資料，不能直接宣稱可見皮膚 |
| 敞開長版襯衫＋高領連身上衣 | 要讀內層連續軀幹覆蓋，不得由外套敞開推論露腹 |
| 雙肩露出 → 腹部 | 領口下降不是腹部開口證據 |
| 上身全無 → 腹部 | 沒有額外上身不代表裸露，還可能有連身、套裝或特殊穿搭 |

這些英文片段是證據，不是直接串接的局部成品 Prompt。沒有將樣本以外款式自動標成已審核；也未根據參考圖片替未明確描述的衣物補露膚資訊。

## 4. 子區域與層次的必要性

將「鎖骨／胸口」或「腰腹／肚臍」整組只標露出／遮住會出錯：鎖骨可能露出但上胸仍有衣料，肚臍可能位於拉鍊開口而腹側仍覆蓋。

契約因此加入內部 `mixed` 狀態，要求指出子區域；不新增 UI 選項，也不增加裸露程度。每個子區域必須依外到內的實際層次判斷：

- 透明外層不會讓不透明內層消失。
- 敞開外層只解除該外層覆蓋，不能解除內搭。
- 露肩 modifier 只影響來源定義的肩線／領口，不能連帶開啟腹部。
- 若資料不足，保留確認的局部表面；若無法確認任何局部身份，使用待補資料狀態，不回退到完整穿搭。

下一階段應先建立少量明確款式的資料 adapter 與以上正反案例，再擴大來源覆蓋。不得把 unknown 降級通過當作完整目錄支援完成。

## 5. 其他已確認的接入缺口

- `webapp/src/features/saved-cards/cardCodec.js` 的 `sanitizeStoredPrompt` 目前把 extraPrompts 重建成 `id／label／text`。新部位與版本直接加在 entry 上會被丟掉；後續 codec 必須實作明確白名單與新舊 round-trip fixtures。
- `webapp/src/lib/page1PromptOutputs.js` 用固定清單列出衍生卡片與圖像來源；新增 extraPrompts entry 不會自動顯示第七張卡。
- `engine.js` 的主投影場景仍縮短而非完全省略，仰躺表面有保留例外；局部 adapter 必須獨立，不沿用既有 bucket。
- 角色卡永久身份契約只在新局部輸出按可見區域做例外；現有六份輸出的身份保留不可修改。
- 光線、膚質、頭髮與特殊穿搭的混合文字需要可追溯局部來源；第一階段尚未建立這些 adapter。

## 6. 第一階段驗證含義

`node --test webapp/src/lib/engine/localDetailPromptContract.test.js` 驗證：不可變且可序列化的契約、三部位允許清單、十組來源引用、覆蓋狀態與範圍、未接入公開輸出。它**不驗證生成畫面、不驗證尚未實作的 renderer 或 codec**。

未接入階段不啟動 Browser 或修改使用者狀態。第二階段必須新增真正的輸入→局部結果測試；第三階段才驗證實際 UI、保存、生成來源。完整六輸出逐字不變等待 adapter 接入後比較，不能靠本次常數測試冒稱已通過。
