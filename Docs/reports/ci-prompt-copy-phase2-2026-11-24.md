## 分流與反例

分流器驗證既有 Git 物件，不依 dirty 工作區或只靠檔名放行。自動測試涵蓋：完整舊全文尾端追加、別名刪除／修改／重排／任意追加、重複 JSON key、ID／名稱／語意／成員變更、生成物竄改、混入程式或 policy 修改、缺 ledger／未知 hash、累積修訂鏈、既有 ledger 不可改寫、跨項目英文碰撞、累積文件檢查、RNG／selection／非目標差異、必要工作失敗／取消／跳過、缺完整部署祖先及最新部署尚未成功。

拋棄式真實 catalog 試改將直筒牛仔褲的 `clean denim texture` 改為 `subtle denim texture`，保留第一分句及其他內容，並在正式 `legacyPromptAliases` 尾端追加完整舊英文。正式 generator 同步後產生修訂記錄。此試改不代表核准新的產品文案。

實際分類結果：基礎建設提交走 `full`；只有 catalog 文案、精確 alias、生成物與 ledger 的後續提交走 `copy`。部署 API 的組合情境使用合成回應測試，沒有偽稱為遠端實跑。

## 歷史覆蓋的處理

完整模擬揭露七個直接釘住舊英文／舊 hash 的測試入口。它們在存在 copy revision 時，以精確 Git 來源還原的隔離 catalog 執行原斷言；沒有 revision 時執行原路徑。原測試內容另用 infrastructure manifest 對照正式基準，未重錄任何 frozen baseline、刪除案例或修改原斷言。當前來源則由獨立前後探針與原功能測試驗證。

初次完整試跑也驗證到未知 Buffer 必須保留原物件，以及同次 shared snapshot 測試期間不能更動受驗證來源；最終完整試跑採固定副本，不在執行期間編輯它。失敗的試跑不計入通過證據。
