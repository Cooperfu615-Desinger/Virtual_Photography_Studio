# A2：單人特殊穿搭色系歸屬

2026-10-27；本批固定 main `15580949ac1f00e7a2628209d91a301434504965`。

## 問題與決策

單人特殊穿搭清理整個 wardrobe section，僅排除三個特殊穿搭選項，誤清其自身 `completeLookPaletteId`。雙人接管清單則本來保留 A／B 色系。90 款 × 九色系在手動選色、收藏套用及後續更新皆可重現。原 JSON／完整 Markdown／引擎來源保有色系，啟動初始化也能保留；這不是上一批 runtime 改句的回歸。

只將單人完整造型色系排除於特殊穿搭接管清理，沿用所有其他清理與模式判斷。不做只對 restoringSelection 有效的例外，因為手動操作和後續任一更新也經過相同流程。不刪除整個接管規則，不更動雙人清單，不在 renderer 補字，也不重新設計色系儲存。

這會讓工作台正確保留使用者選色；其他衣物、鞋襪、配件仍由特殊穿搭接管。相同選值進入引擎的輸出及 RNG 完全相同。色系已被歷史版本清掉的卡片無法推測補回，公開原文與既有抓拍快照保持。

## 後續邊界

上下配色的無獨立 ID 顏色成分被抓拍驗證拒絕，與舊連身回填互斥／純文字歸屬不足，分屬後批。本次以固定案例確認其狀態保持。所有既有 runtime／A2／A1／A5 與 A～E 封存為歷史證據；新 inverse 在隔離副本還原舊 transition，再執行原歷史工具。
