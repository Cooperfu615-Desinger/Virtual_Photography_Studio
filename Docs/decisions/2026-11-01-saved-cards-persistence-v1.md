# Saved Cards 持久化 v1：規格提案與範圍決策

日期：2026-11-01。基準：main `60c46d39ef0524c9b641c771e6319fb5d4b2e091`。

狀態：最初授權制定規格；2026-11-01 使用者後續依規格授權 A 階段，範圍見文末。B～D 產品實作、正式資料遷移、提交及推送未授權。

## 背景

現行收藏保存在 localStorage；2,250,000 UTF-8 bytes 是應用程式預算，122 並非固定筆數上限。保存超出預算或瀏覽器容量時會縮減清單；雲端操作佇列只在記憶體，短暫通知也無法充分區分畫面存在、本機保存與雲端確認。以上為原始碼分析，不代表本輪已讀取私人收藏或確認使用者實際遺失資料。

既有[下載修復](../specs/saved-cards-download-resilience-v1.md)處理匯出失敗與備份退路，沒有解決本機保存容量及離線同步意圖的持久化；兩者不能互相替代。

## 擬採方案

詳細契約及 SC-P01～SC-P15 見[Saved Cards 持久化 v1](../specs/saved-cards-persistence-v1.md)。

1. IndexedDB 作本機正式來源，以交易完成作為保存成功；不自動裁切收藏。不僅提高 localStorage 預算，因為那仍保留整份同步寫入與容量失敗問題。
2. Firestore 作現有授權帳號的同步副本；不採雲端唯一來源，保留離線與未登入的本機使用。
3. 卡片變更與待同步操作同交易保存，刪除有持久記錄；待同步工作按 UID 綁定、逐項確認，不因登出丟棄或改送其他帳號。
4. 同 origin 本機共用 Library 維持；卡片 ID、版本、Prompt 原文、未知欄位與舊來源快照保留。儲存容器升版不重寫歷史卡片。
5. 舊來源先快照、隔離搬移、讀回核對再切換；不持續雙寫。未知／損壞資料與同 ID 衝突不得自動捨棄。
6. 舊分頁寫入、帳號切換、雲端同 ID 衝突與回退列入正式驗收；單純保留舊 localStorage 不等於可以安全回退。

## 必須隨規格審閱的使用行為

- 保存成功提示延至本機交易完成；常駐狀態分開本機與雲端，沿用現有視覺，不改工作區導航。
- 同 ID 雲端差異保留雙方，需明確選擇，不再以本機優先顯示推定可覆寫雲端。
- 清空的雲端刪除集合固定為確認時已載入、與目前 UID 對應的卡片；不在延後重試時掃除雲端新出現的全部卡片。
- 無法完整遷移時先提供唯讀預覽／原始備份與恢復流程；不得誤報成功或用空清單蓋回。

以上是具體提案，尚未改變現行產品；後續實作應先確認本規格，而非在實作中另行猜測。

本批只新增規格、本決策及專案狀態入口。文件檢查與將來產品驗收分開；不啟動服務、不讀寫瀏覽器收藏、不操作雲端私人資料、不付費生成。既有歷史基準及瀏覽器限制不改寫；已結案的資料庫與 DLL 工作不重開，PAGE2 舊匯入、J12、P5b 不併入。
